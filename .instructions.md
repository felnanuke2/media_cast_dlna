# Media Cast DLNA - Copilot Instructions

## Project Overview

**Media Cast DLNA** is a Flutter plugin for discovering and controlling DLNA/UPnP media devices on local networks. It enables developers to cast media to smart TVs, speakers, and other DLNA-enabled devices.

- **Type**: Flutter Plugin (Pigeon-based native bridge)
- **Primary Platform**: Android (iOS support was removed due to Apple privacy restrictions)
- **Minimum SDK**: Flutter 3.3.0+, Dart 3.8.1+
- **Package Name**: `media_cast_dlna` (v0.2.0)
- **License**: MIT

### Core Tech Stack

- **Dart/Flutter**: UI layer and high-level API
- **Kotlin**: Android native implementation
- **jUPnP**: UPnP/DLNA protocol implementation (Android)
- **Pigeon**: Code generation for Dart ↔ Native communication
- **Kotlin Coroutines**: Async operations on Android

## Architecture Overview

### Plugin Structure (Pigeon-Based)

```
┌─────────────────┐
│  Flutter App    │ (Uses MediaCastDlnaApi + controller)
├─────────────────┤
│   Pigeon Layer  │ (Method channels + callbacks)
├─────────────────┤
│ Platform Layer  │ (Native implementation)
│  ├─ Android     │ (MediaCastDlnaPlugin + Managers)
│  └─ iOS         │ (Placeholder - not implemented)
└─────────────────┘
```

### Key Architectural Principles

1. **Pigeon Code Generation**: All cross-platform communication is defined in `pigeons/media_cast_dlna.dart`
   - Generates Dart → Kotlin → Swift bindings automatically
   - Ensures type safety and reduces boilerplate

2. **Manager Pattern (Android)**: Single Responsibility Principle
   - `DeviceDiscoveryManager`: DLNA device discovery
   - `MediaControlManager`: Playback control (play/pause/seek)
   - `VolumeManager`: Volume and mute operations
   - `BaseManager`: Common validation and utilities

3. **Object Calisthenics**: Value objects for domain concepts
   - `DeviceUdn`, `VolumeLevel`, `TimePosition`, etc.
   - Extensions add behavior while maintaining simple DTOs
   - Provides type safety and semantic clarity

4. **Controller Pattern (Dart)**: High-level abstraction
   - `MediaCastDlnaController`: Singleton for app-wide access
   - Stream-based event handling
   - Convenience methods for common operations

5. **Coroutines (Android)**: Non-blocking async operations
   - All long-running operations use `suspend` functions
   - Prevents ANR errors from blocking main thread
   - Concurrent operations with `async/await`

### Core API Methods (HostApi)

```dart
abstract class MediaCastDlnaApi {
  // Discovery
  Future<void> startDiscovery(DiscoveryOptions options);
  Future<void> stopDiscovery();
  Future<List<DlnaDevice>> getDiscoveredDevices();

  // Playback Control
  Future<void> play(DeviceUdn deviceUdn);
  Future<void> pause(DeviceUdn deviceUdn);
  Future<void> stop(DeviceUdn deviceUdn);
  Future<void> setMediaUri(DeviceUdn deviceUdn, String mediaUri, String metadata);
  Future<void> seek(DeviceUdn deviceUdn, TimePosition position);

  // Volume Control
  Future<void> setVolume(DeviceUdn deviceUdn, VolumeLevel level);
  Future<void> setMute(DeviceUdn deviceUdn, MuteOperation operation);
  Future<VolumeInfo> getVolumeInfo(DeviceUdn deviceUdn);

  // State Queries
  Future<PlaybackInfo> getPlaybackInfo(DeviceUdn deviceUdn);
  Future<TransportState> getTransportState(DeviceUdn deviceUdn);
  Future<TimePosition> getCurrentPosition(DeviceUdn deviceUdn);
  Future<bool> isDeviceOnline(DeviceUdn deviceUdn);

  // Events
  Future<void> subscribeToEvents(DeviceUdn deviceUdn, String serviceType);
  Future<void> unsubscribeFromEvents(DeviceUdn deviceUdn, String serviceType);
}
```

### Core Data Models

**Value Objects** (semantic wrappers, follow object calisthenics):
- `DeviceUdn`: Unique device identifier
- `VolumeLevel`: Volume percentage (0-100)
- `MuteState`: Mute status (boolean wrapper)
- `TimePosition`: Playback position in seconds
- `TimeDuration`: Duration in seconds
- `Url`: URI/URL (string wrapper)
- `IpAddress`: Network IP address
- `NetworkPort`: Network port number
- `DiscoveryTimeout`: Timeout in seconds
- `SearchTarget`: SSDP search target string

**Complex Models**:
- `DlnaDevice`: Complete device descriptor with manufacturer/model details
- `DlnaService`: UPnP service (AVTransport, RenderingControl, ContentDirectory)
- `PlaybackInfo`: Current playback state and metadata
- `VolumeInfo`: Volume level + mute state
- `MediaMetadata` (sealed): Audio/Video/Image metadata for DIDL conversion

        val (_, service) = requireDeviceAndService(deviceUdn, "AVTransport")
        // ...
    }

### Kotlin Coroutines: Suspend Functions

**Never block the main thread. Always use suspend functions:**

```kotlin
// ✅ CORRECT - Non-blocking
suspend fun play(deviceUdn: String) {
    val (device, service) = requireDeviceAndService(deviceUdn, "AVTransport")
    controlPoint.playSuspending(service)
}

// ❌ WRONG - Blocking with Semaphore
fun play(deviceUdn: String) {
    val semaphore = Semaphore(0)
    service.execute(object : Play(service) {
        override fun success(invocation: ActionInvocation<*>?) {
            semaphore.release()  // BLOCKS!
        }
    })
    semaphore.tryAcquire(5, TimeUnit.SECONDS)
}
```

### JupnpExtensions: Suspend Wrapper Functions

**Location**: `core/JupnpExtensions.kt`

These wrap jUPnP callbacks into Kotlin suspend functions:

```kotlin
// Example structure
suspend fun ControlPoint.playSuspending(service: Service) = 
    suspendCancellableCoroutine { continuation ->
        val action = Play(service)
        action.setInstanceId(0)
        
        execute(object : PlayActionCallback(action) {
            override fun success(invocation: ActionInvocation<*>?) {
                continuation.resume(Unit)
            }
            override fun failure(invocation: ActionInvocation<*>?, error: UPnPFailure?) {
                continuation.resumeWithException(
                    Exception("Play failed: ${error?.message}")
                )
            }
        })
    }
```

### Concurrent Operations

**Execute multiple operations in parallel** using `async`:

```kotlin
suspend fun getPlaybackInfo(deviceUdn: String): PlaybackInfo = coroutineScope {
    val (_, service) = requireDeviceAndService(deviceUdn, "AVTransport")
    val controlPoint = requireUpnpService().controlPoint
    
    // Run queries concurrently
    val transportDeferred = async { 
        controlPoint.getTransportInfoSuspending(service) 
    }
    val positionDeferred = async { 
        controlPoint.getPositionInfoSuspending(service) 
    }
    
    val transportInfo = transportDeferred.await()
    val positionInfo = positionDeferred.await()
    
    return PlaybackInfo(
        state = transportInfo.toTransportState(),
        position = parseTimeToSeconds(positionInfo?.relTime),
        duration = parseTimeToSeconds(positionInfo?.trackDuration),
    )
}
```

### Plugin Facade Pattern

**MediaCastDlnaPlugin** delegates to managers:

```kotlin
class MediaCastDlnaPlugin : FlutterPlugin, MediaCastDlnaApi {
    private val pluginScope = CoroutineScope(SupervisorJob() + Dispatchers.IO)
    
    private val mediaControlManager by lazy {
        MediaControlManager(upnpService)
    }
    private val deviceDiscoveryManager by lazy {
        DeviceDiscoveryManager(upnpService, upnpRegistryListener)
    }
    
    override fun play(deviceUdn: String, callback: (Result<Unit>) -> Unit) {
        pluginScope.launch {
            try {
                mediaControlManager.play(deviceUdn)
                callback(Result.success(Unit))
            } catch (e: Exception) {
                callback(Result.failure(e))
            }
        }
    }
}
```

## Important Constraints & Limitations

### Platform Limitations

1. **Single Android**: iOS support not maintained
2. **Local Network Only**: DLNA discovery limited to LAN
3. **Multicast Dependency**: Requires WiFi with multicast support (not all cellular networks)
4. **Concurrent ANR Risk**: Must use coroutines - never block in native code
5. **Time Parsing**: Some devices send non-standard time formats (handled in utilities)

### DLNA Limitations

1. **Device Variability**: Manufacturer implementations vary significantly
2. **Metadata Support**: Not all devices support DIDL metadata (graceful degradation needed)
3. **Concurrent Commands**: Some devices require sequential commands (no parallel control)
4. **Event Subscription Timeouts**: Some devices drop subscription connections (require polling)
5. **Volume/Mute Availability**: Not all renderers support volume control

### When to Use Polling vs Events

```dart
// Use event subscriptions when:
// - Real-time updates needed
// - Bandwidth available
// - Device reliably supports subscriptions

await controller.subscribeToEvents(deviceUdn, 'AVTransport');
controller.onTransportStateChanged.listen((event) { /* ... */ });

// Use polling when:
// - Events unreliable
// - Device frequently disconnects/reconnects
// - Baseline stability needed

Timer.periodic(const Duration(seconds: 1), (_) async {
    final state = await controller.getTransportState(deviceUdn);
});
```

## Troubleshooting

### Common Issues

**"Device not responding"**
- Check WiFi connectivity and multicast support
- Verify device is DLNA-compatible
- Wait 3-5 seconds after discovery before issuing commands
- Some devices require subscription before accepting commands

**"ANR (Application Not Responding)"**
- Never use Semaphore-based blocking
- Ensure all UPnP operations use suspend functions
- Check for main-thread blocking in callbacks

**"Volume not changing"**
- Not all DLNA devices support volume control
- Use try-catch when setting volume
- Check device capabilities before UI (fallback to device controls)

**"Metadata not displaying"**
- Some devices don't support DIDL metadata parsing
- Gracefully degrade to basic Title/URI display
- Test with multiple device types

**Code generation issues**
